About

A DevOps engineer who treats infrastructure as software: versioned, reviewed, tested and observable.

I design and deploy scalable, highly available systems on AWS, and I have hands-on exposure to GCP and Azure. Day to day I work with Kubernetes, Terraform, Docker and Helm, and I automate the full CI/CD lifecycle across Jenkins, GitHub Actions and GitLab CI/CD.

I build security checks into pipelines instead of adding them at the end, using SonarQube for code quality gates. Releases go out through GitOps with Argo CD, so the state of every environment is in Git and every change can be traced and reverted.

I write reusable Terraform modules that can be applied across environments, manage Linux servers with shell scripting and Ansible, and keep systems observable with Prometheus and Grafana dashboards built around uptime and service-level objectives.

    Engineering principles

    The standards I hold my own work to.

    Everything in version control

    Infrastructure, pipelines and configuration live in Git and change through pull requests and review.

    No manual production changes

    If a change cannot be made through code and a pipeline, it is not ready for production.

    Design for failure

    Multi-AZ data stores, load-balanced stateless tiers and autoscaling so a single failure does not cause an outage.

    Make rollback easy

    With GitOps, returning to a known-good release is a revert in Git, not an emergency procedure.

    Least privilege

    Scoped IAM roles, private subnets and encrypted data, with a bastion as the only controlled entry point.

    Measure what matters

    Dashboards and alerts are tied to uptime and service-level objectives, not just raw resource graphs.
